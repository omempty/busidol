# 04. 게임 시스템 분석

> Godot 이식 시 "무엇을 그대로 옮기고, 무엇을 개선할지" 판단 기준을 제공한다.

## 1. 필드 시스템

### 1.1 좌표 체계 (이원 좌표)

```
맵 전체: 200×65 타일
카메라 원점: (mapx, mapy)   ← 화면 좌상단
화면 뷰:    19×15 타일 (12px)
플레이어:   (x,y) 0..18 / 0..14  로컬 타일 좌표
실제 맵셀:  (mapx+x, mapy+y)
```

- 이동: x/y가 경계(4/12, 4/9)에 도달하면 mapx/mapy를 움직여 카메라 스크롤,
  아니면 캐릭터만 이동. **Godot에서는 Camera2D + limit으로 자연 해소**하되,
  "타일 단위 격자 이동 + 즉시 방향전환"의 원작 감각은 유지 권장.
- 스프라이트: `mode` 0~7 = 아래/위/왼쪽/오른쪽 × 2프레임 (I.SPR 인덱스).
- 캐릭터는 논리적으로 **2×2 타일 점유** (충돌 검사가 항상 인접 2셀 짝으로 수행).

### 1.2 충돌/통행 규칙

| 조건 | 동작 |
|---|---|
| 진행 방향 앞 2셀 ATT ∈ {0, 2} | 통과 |
| 그 외 (1, NPC ID, 상자 150+, 방ID 등) | 차단 |
| 발밑(아래 2셀) ATT==9 + 아래키 | 문 연출 후 `mapy += 3` (위 문이면 -3) |
| 계단 고정 좌표 4곳 + 아래키 | walk_floor() 층 전환 애니 → f±1 → load_map |

층 전환 좌표(맵 셀): (100,63)↔다음층+3타일 / (103,63)↔이전층-3 / (169,60)+8 / (177,60)-8.
**주의**: 모든 층(F0~F5)이 같은 좌표를 공유 — 맵 데이터가 좌표에 의존함을 변환기가 보존해야 함.

### 1.3 렌더링 순서

`Print_Tile()` = 타일 → 오브젝트(OBJ>0) 순. 캐릭터/적/NPC는 매 프레임 위에 그림.
ATT==2 셀은 캐릭터 발을 가리도록 타일+오브젝트 재렌더(GOODITEM.C L402-409).
→ Godot: TileMapLayer ground/object 2개 + y-sort 또는 ATT==2 셀을 별도 "front" 레이어로.

## 2. 몬스터 시스템

### 2.1 필드 스폰/AI (move_enemy)

- 최대 8체(`MAX_EYE`). 사망 시 life=0 → 다음 틱에 층별 난수 테이블로 리스폰:

| 층 f | HP | AP/DP | EXP | 돈 | Level |
|---|---|---|---|---|---|
| 0 | 11+rnd10 | 11+rnd10 | 2+rnd3 | (1+rnd1)×100 | 1+rnd3 |
| 1 | 20+rnd45 | 20+rnd40 | 5+rnd5 | (2+rnd3)×100 | 4+rnd3 |
| 2 | 125+rnd65 | 90+rnd45 | 10+rnd10 | (2+rnd4)×100 | 7+rnd3 |
| 3 | 270+rnd170 | 165+rnd30 | 15+rnd15 | (2+rnd5)×100 | 10+rnd3 |
| 4~5 | 650+rnd155 | 240+rnd45 | 20+rnd20 | (2+rnd6)×100 | 13+rnd4 |

- AI: `PATTERN[10][40]` 사전 정의 웨이포인트(방향 시퀀스, 0=정지).
  **플레이어가 같은 화면에 보이면 패턴 무시하고 직진 추격**(충돌 셀 검사 포함).
- 접촉(x±1, y±2) → `WarMode()` 전투 개시. 전투 종료 후 무조건 exp/money 지급 + 해당 적 소멸.

### 2.2 전투 (WarMode)

```
턴 구조:
  플레이어 메뉴 선택 ──► 공격 데미지 = (Ap + rnd(10)) / 4
                     └── 도구(장착 교체) / 상태창 / 설정 / 도망(항상 성공)
  적 턴            ──► 데미지 = (Power + rnd(10)) / 6   (Defence 미사용!)
  HP 0             ──► 승리(-1)/패치 처리, 도주(0), 패배(-1) 구분 없이 exp/money 지급
```

- **Defence(DP) 스탯이 데미지 공식에 미반영** — 원작 밸런스 결함. 이식 시 유지 or 수정 결정 필요.
- 연출: 격투게임 패러디. 플레이어 공격 랜덤 6종(a1/a3/a5.spr), 적 회피 6종(d*.spr),
  적 공격은 e1~e8.spr + fire.spr 투사체. 페이지 복사 기반 수동 애니메이션.
- WVISUAL=ON/OFF로 연출 생략 가능(설정 메뉴).

## 3. 대화 시스템

- 호출부 `Talk()`: 전방 2셀 ATT → NPC ID 매핑 → 함수 호출 (~22종).
- `Talk_Window(name, startIdx, lineCount)`: 대사창 + 이름 + 3줄 단위 페이징,
  키 입력 또는 타임아웃(PRINT_RATE 루프)으로 진행.
- NPC별 **플래그 상태 기반 분기**: 예) 화공과 퀘스트 체인

```
v_Howa=0: 교수 대면 → "약품 가져와"      (v_HowaJo=1 설정)
v_Howa=1: 조교 변명 장면 → v_HowaJo=2, v_Howa=1...
v_Howa=2: 약품 획득 후 완료 대사
v_Hong:   남앵골교수(v_Nam) 대면 여부에 따라 홍춘발 교수 대사 3단 변화
v_Quan:   아이템 먹은 횟수 0~3에 따라 권영칠 교수 대사 4종
```

→ Godot에서는 **DialogueTable(JSON) + GameFlags 조건 평가기**로 일반화.
원작처럼 하드코딩 switch 대신 데이터 주도 구조 권장 (→ 02_design/01_oop_redesign.md §4).

## 4. 아이템/인벤토리

- 상자: 맵 ATT 150+ = 아이템 ID. 개봉 시 `item_flag[f][n]`에 좌표 기록, ATT→1·OBJ→153/154(빈상자).
  층 재진입 시 `refresh_item()`이 개봉 상태 복원.
- 인벤토리 `view[50]`: {att(스프라이트ID 150+), num} 중첩 배열. 최대 50종.
- 특수 아이템: DON1~3(현금 즉시 획득), MEET(198: 개봉 시 몬스터 전투), EMPTY(199).
- 장비 개념: 전투 중 도구 메뉴에서 선택한 아이템 1개가 `ItemEat`로 장착되어
  Hp/Ap/Dp/Money에 가산(해제 시 차감). **장착 중 피격 시 수치 훼손 버그 여지**.
- 상점(store): 음식 6종 구매로 HP 회복. 현금 차감.

## 6. UI/메뉴

- 메인 메뉴(ENTER): 도움말 / 아이템보기(Viewer) / 저장·불러오기(io, **미구현**) / 기타(gitar: 지도·속도·음악).
- HUD: 우측 패널(TEST_F.PCX 프레임)에 Level/Exp/HP/AP/Money 8자리 숫자(NUM[] 스프라이트).
- 메시지: MSG 매크로(중앙 한글 출력), Put_Msg(윈도우+텍스트).
- Godot에서는 Control 노드 계층(HUD/MenuLayer/DialogueBox)으로 재구성.

## 8. 원작 vs Godot 이식 시나리오 매핑 요약

| 원작 메커니즘 | Godot 대응 | 변경도 |
|---|---|---|
| asm 픽셀 스크롤 | Camera2D(position smoothing) | 대체 |

| XMS 32B 대사 레코드 | JSON/Resource 대사 테이블 | 동등 이식 |
