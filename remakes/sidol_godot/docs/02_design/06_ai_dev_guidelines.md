# 06. AI 바이브 코딩 개발 가이드라인

> 본 프로젝트는 **AI 에이전트 중심의 개발(vibe coding)**을 전제로 한다.
> 아키텍처는 이미 이에 맞춰 설계됨 — 이 문서는 그 이유와 실행 규칙을 고정한다.

## 1. 왜 이 아키텍처가 AI 친화적인가

| 설계 결정 | AI 관점 효과 |
|---|---|
| **데이터가 계약**(JSON 스키마 ↔ 런타임) | AI가 코드를 유추할 필요 없이 스키마만 보고 양쪽을 독립 생성 가능 |
| **컴포지션 우선, 상속 최소화** | 깊은 클래스 계층 추적 실패(AI 최대 약점) 회피. 각 컴포넌트가 격리된 작업 단위 |
| **Op 레지스트리 패턴** | 새 op 추가 = 한 파일에 enum+핸들러 추가. 확산 없는 국소 수정 |
| **Validator 선배치** | AI가 만든 콘텐츠의 참조 오류를 사람 검토 전 자동 차단 |
| **툴=Godot 플러그인(별도 앱 아님)** | 프레임워크 하나만 학습. Electron/Tauri 등 제2 스택 부재 |
| 원작 소스 = **명세서로만 사용** | C 코드를 포팅하는 게 아니라 [분석 문서](../01_analysis/)를 읽고 재구현 — 레거시 맥락 오염 차단 |

## 2. 저장소 규칙 (AI가 항상 따를 것)

### 2.1 파일 규모와 응집도

```
스크립트 1개 = 책임 1개, 권장 ≤200행 / 상한 300행.
초과 시 컴포넌트 분리 (예: EnemyEntity → ChaseAI + HealthComponent).
파일 경로 = 역할 (res://src/entities/enemy/chase_ai.gd).
한 디렉터리 = 한 시스템. 디렉터리마다 README.md 10~20행 (무엇이 어디 있나).
```

- 근거: AI 컨텍스트 창은 유한하다. 파일이 작을수록 전체 파일을 프롬프트에 넣을 수 있어
  환각(hallucination)과 절반짜리 수정이 급감한다.

### 2.2 네이밍/스타일 고정표

| 대상 | 규칙 | 예 |
|---|---|---|
| 클래스(Resource) | PascalCase + `Def`/`Table` 접미 | `ItemDef`, `EncounterTable` |
| 노드 스크립트 | snake_case 파일명 = 클래스명 | `chase_ai.gd` → `class_name ChaseAI` |
| 시그널 | 과거형 동사 | `encounter_started`, `item_obtained` |
| 오토로드 | 명사 싱글턴 | `GameState`, `EventBus` |
| JSON 키 | snake_case | `schema_version`, `npc_id` |
| 상수 | SCREAMING_SNAKE | `TILE_PX`, `MAX_FLOORS` |

### 2.3 AGENTS.md (저장소 루트, 첫 커밋에 생성)

AI 코딩 도구가 자동으로 읽는 진입점. 내용 골격:

```markdown
# BSD 시돌이의 모험 — Godot 리메이크
- Godot 4.x / GDScript. 정적 타입(: int 등) 필수.
- 문서 지도: docs/01_analysis(원작 명세) docs/02_design(설계)
             docs/03_plan(진행) docs/04_scenario(★마스터 시나리오 = 권위)
- 작업 시작 전: 해당 시스템 README + 관련 스키마 먼저 읽기.
- 절대 금지: @ts-ignore류 무시, 기존 테스트 삭제, docs와 다른 매직넘버 하드코딩.
- 완료 정의: 헤드리스 임포터 통과 + 스모크 씬 실행 + Validator 0오류.
```

## 3. 검증 루프 (모든 AI 작업의 완료 조건)

```
작업 → gdformat/lint → 헤드리스 검증 → (가능시) 스모크 → 보고
         │                  │                │
         │                  ├─ tools/import_all.gd    데이터 임포트+스키마
         │                  └─ tools/validate.gd      참조/플래그 검사
         └────────────────────────────────────────────
스모크: godot --headless res://tests/smoke.tscn
        - 부팅→필드 로드→1타일 이동→대사 열기→종료 (자동 시나리오)
```

- **원칙**: AI는 "완료" 주장 전에 위 명령의 실제 출력을 붙여야 한다. 출력 없는 완료 보고 = 미완료.
- 유닛테스트(GUT/GdUnit4)는 순수 로직(DamageCalculator, Inventory, 조건평가기)에만.
  씬/UI는 스모크+수동 QA 담당 — 테스트 유지보수 비용 방어.

## 4. 태스크 분해 규격 (AI에게 시키는 단위)

한 번의 AI 작업 = 다 3개 조건을 만족하는 최소 단위:

```
1. 범위: 파일 N개 이내 (권장 1~3), 새 시스템이면 디렉터리 1개
2. 인터페이스 먼저: 시그니처/스키마를 사람이 승인 후 구현 지시
   (예: "DamageCalculator.calculate(atk:int,rng:int)->int, 원작 공식 (atk+rnd10)/4")
3. 수용 기준: 실행 가능한 검증 명령 포함
```

- **금지된 던지기**: "RPG 만들어줘", "전투 시스템 완성해줘" 같은 거대 프롬프트.
  로드맵(01_roadmap.md)의 각 Phase가 곧 태스크 목록이다.
- **컨텍스트 주입 표준**: 작업 지시에는 항상 (a)관련 문서 링크 (b)스키마 원문 (c)참조할
  기존 파일 1~2개를 함께 준다.

## 5. 인간 담당 vs AI 담당 경계

| 영역 | 주체 | 이유 |
|---|---|---|
| 변환기(CLI), CRUD 에디터, 반복 UI | **AI** | 스펙이 완전히 닫혀 있음 |
| 데이터 스키마 변경, Op 추가 | 인간 승인 → **AI 구현** | 파급면이 넓음 |
| 시나리오 집필/개편 | **인간** (AI 초안 가능) | 유머·패러디 톤이 원작 생명 — 04_scenario 참조 |
| 아트 리터칭 방향, 게임필 감 | **인간** | 취향 영역 |
| 밸런스 수치 | 인간 방향 → **AI 표 생성** | LEVELsruct 등 원작 표 기반 |
| 코드 리뷰 | AI 1차 + 인간 최종 | 스키마·문서와의 일치성 중심 |

## 6. AI 특유 리스크와 구조적 방어 (요약 — 상세는 03_plan/02)

| 리스크 | 방어 장치 |
|---|---|
| 환각 API 사용 | 버전 고정(Godot 4.x), 스모크 실행 강제 |
| 세션 간 컨텍스트 손실 | 문서가 단일 진실원천. 코드보다 문서 먼저 갱신 |
| 스타일 표류 | §2.2 고정표 + gdformat 강제 |
| 절반짜리 대규모 수정 | §4 파일 수 상한, 인터페이스 선승인 |
| 테스트 게임화 | Validator/스모크는 CI에서만 결과 인정 |

## 7. 즉시 실행 항목 (Phase 0에 포함)

1. `AGENTS.md` 작성
2. `tools/import_all.gd` / `tools/validate.gd` 골격 + 빈 스모크 씬
3. `gdformat` 설정(.pre-commit 또는 CI 스크립트)
4. 스키마 v1 파일 3종(events/cutscenes/battle_moves) 빈 껍데기 + JSON Schema
5. 디렉터리 README 자동 생성 템플릿

## 8. 에셋 생성 AI (코드 에이전트와의 경계)

아트·오디오는 **외부 AI 생성**이므로, 코드 에이전트와 별개의 워크플로가 필요하다.
인터페이스 계약은 [07_ai_asset_pipeline](07_ai_asset_pipeline.md)에 위임하며,
본 가이드라인과의 접점만 고정한다:

| 규칙 | 내용 |
|---|---|
| 읽을 문서 | 생성 작업 전 `gen/_index.md`(자동 렌더) + `style_bible.md`만 읽음 — spec JSON 직접 해석 불요 |
| 산출물 위치 | 반드시 `assets/raw/`로만. `res://assets/` 직접 기록 금지(게이트 우회) |
| 채택 권한 | Validator 통과 + 사람(또는 리뷰 에이전트) 승인분만 컨버터 통과 |
| 프롬프트 관리 | 프롬프트는 spec에서 렌더된 것만 사용 — 수동 편집본은 CI drift 검출 대상 |
