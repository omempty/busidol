# 그래픽 LLM 의뢰 가이드 (운영자용 — 따라 하면 되는 순서)

> 목적: 이미지 생성 LLM에 에셋을 의뢰하고, 납품을 검증·설치하는 전체 사이클.
> **경로·규격의 단일 출처는 [LLM_WORKFLOW.md](LLM_WORKFLOW.md)다.** 이 문서는 실행 순서만 다룬다.
> 곁눈질용 1장 요약은 [PROMPTING_QUICKGUIDE.md](PROMPTING_QUICKGUIDE.md).
> 최종 갱신: 2026-08-29(8차 세션 — 게이트 3종·설치 단계·셀 편집기·GUI 없는 경로 반영).

## 이 문서는 누구 것인가 (중요)

**이 문서를 그림 그리는 LLM에게 주지 마라.** 사이클을 *운영하는* 쪽 문서다.

| 상대 | 줄 것 |
|---|---|
| **이미지 생성 LLM** | 해당 패키지의 `prompt.md` 전문 + 그 안 "입력 (첨부)" 목록의 파일 전부. 그게 전부다 |
| **웹 채팅(무료 LLM)** | 묶음의 `웹붙여넣기.md` 본문 + 거기 지정된 이미지 3~4장 |
| **운영하는 사람/에이전트** | 이 문서 + `AGENTS.md`의 "에셋 에이전트 작업 경계" |

`prompt.md`는 규격·금지규칙·첨부 설명이 자기완결로 들어 있다. 이 가이드를 같이 주면
그림 LLM이 폴더 구조·심사 절차 같은 무관한 지시를 따라간다.

## 0. 사전 준비 (새 PC)

```powershell
git clone https://github.com/omempty/busidol.git
cd busidol/remakes/sidol_godot
pip install pillow numpy          # 패키지 생성기·검증기 의존성 (이것만 있으면 됨)
```

- `assets/raw/llm/`은 gitignored — **클론 직후엔 비어 있다. §2로 재생성한다.**
- 원본 도트(`assets/originals_ref/`)·스펙·팔레트는 git에 있어 재생성이 항상 가능하다.
- 심사 보드·셀 편집기는 파이썬 표준 라이브러리만 쓴다(추가 설치 없음).

## 1. 지금 무엇이 비었나 — 현황판부터

```powershell
현황판.bat        # 다시 굽고 브라우저로 연다(서버 불필요)
```

`현황판.html` 한 장에 카테고리별 진행률, 에셋별 상태, 프롬프트 바로가기, 지금 칠 명령이 있다.

| 상태 | 뜻 |
|---|---|
| **설치됨** | 게임이 실제로 읽는다 |
| **채택(미설치)** | `20_processed`에 있으나 `assets/`로 안 갔다 → `납품처리.bat` |
| **납품 대기** | `10_submitted`에 있고 심사 전 |
| **의뢰 준비됨** | `prompt.md`는 있고 납품이 없다 → 의뢰할 차례 |
| **패키지 없음** | 의뢰 패키지부터 만들어야 한다(§2) |

숫자만 볼 때는 `python tools/dev/asset_status.py` (현황판과 같은 소스).

## 2. 의뢰 패키지 만들기

```powershell
의뢰생성.bat                      # 메뉴에서 카테고리 선택
의뢰생성.bat portraits            # 그 카테고리 전량
의뢰생성.bat portraits prof_mo    # 한 건만 — 시범·부분 재생성
```

| 카테고리 | 무엇 | 규격 |
|---|---|---|
| `portraits` | 대화 초상 16종 | 768×256 (256 셀 3개 = 표정 3종) |
| `effects` | 전투 이펙트 5종 | 셀 128 × 프레임, 1행, **셀 중앙 정렬** |
| `battle_cuts` | 전투 대형 컷 5종 | 셀 **512** × 프레임, 배우만(투명 배경) |
| `battle_actors` | 전투 SD 시트 | 셀 128 격자, 필드 시트와 같은 체계 |
| `monsters` | 몬스터·보스(신규 창작) | 스펙이 정하는 행×열(패키지마다 다름) |
| **리마스터** | 원작 이관 몬스터 8종 — `의뢰생성.bat remaster` | 원작 시트를 신원 근거로, 스펙 행 구성대로 |
| `npcs` | 필드 NPC 4종 | 셀 128 격자 |
| `items` | 아이템 아이콘 40종 | 96×96 1장 |
| `keyart` | 컷신 키아트 6종 | 1920×1080 |

**id를 명시하면 이미 있어도 다시 만든다**(부분 수정용).

**리마스터(`remaster`)는 계약이 다르다.** 신규 창작이 아니라 1995년 원작 도트를 격상하는
일이라, 패키지에 그 몬스터의 **원작 시트 + 원작 SPR 프레임**이 들어가고 프롬프트가
"바꾸지 않는 것(실루엣·색 정체성·크기감) / 격상하는 것(명암 4~6단·질감·색 수) /
새로 그리는 것(원작에 없던 attack·hurt·death 행)"을 나눠 못 박는다.
원작은 보행 4방향 2프레임 + 정지뿐이었고 전투 모션이 없었다 — 그 행들은 원작 실루엣을
근거로 창작한다.
공용 참조(style_ref·scale_ref·subpalette·원작 그림)는 **카테고리 루트에 1부**만 두고
`prompt.md`가 `../파일명`으로 가리킨다. 패키지 폴더에는 그 패키지 전용 파일만 남는다.

## 3. 쉬운 길 (권장) — 몇 건만 묶어서 통째로 넘기기

이미지 생성은 토큰이 비싸다. 전량이 아니라 **골라 담아** 자기완결 폴더로 포장한다.

```powershell
묶음포장.bat --pick 3 --name 시범                     # 비어 있는 것부터 3건
묶음포장.bat monsters:sys_builder effects:hit_spark   # 콕 집어서
묶음포장.bat --cat portraits --pick 2                 # 카테고리 안에서 2건
```

산출: `assets/raw/llm/_batch/<이름>/`

```
작업지시.md              무엇을 몇 장, 어떤 순서로, 어디에 저장할지 (LLM이 첫 줄부터 읽는다)
먼저읽기.md              그래픽 담당 지시서 사본
<카테고리>__<id>/        prompt.md(경로 평탄화) + 첨부 이미지 전부 — 폴더 밖을 참조하지 않는다
  └ 웹붙여넣기.md        웹 채팅용 축약본(2KB 안팎)
_제출/                   여기에 납품 PNG를 받는다
```

### 3-1. 파일 접근이 되는 LLM/에이전트

폴더를 통째로 주고 한 줄만 말하면 된다:

> `_batch/<이름>/` 폴더를 준다. `작업지시.md`를 먼저 읽고 그대로 따르라.

### 3-2. 웹 채팅(무료 LLM, 파일 접근 없음)

각 항목 폴더의 **`웹붙여넣기.md`**를 쓴다. 전문(7~9KB)을 2KB 안쪽으로 줄인 축약본이라
무료 티어에서도 한 메시지에 들어간다.

1. 새 대화를 연다
2. `웹붙여넣기.md`의 **본문을 그대로 붙여넣는다**(맨 아래 "이 파일 쓰는 법" 절은 빼도 된다)
3. 그 문서가 지정한 이미지를 **순서대로 3~4장** 첨부한다
   (격자 템플릿 → 원작 화풍 참조 → 크기 기준 → 색 스왑치)
4. 첨부가 아예 안 되는 채팅이면 본문만으로 진행하되 **크기·프레임 수·색 수**는 반드시 지키게 한다
5. 결과 PNG를 `_제출/<id>_v1.png`로 저장한다(재납품은 `_v2`, `_v3`)

톤 일관성은 축약본의 **스타일 6줄 + 서브팔레트 hex + 첨부한 원작 그림**이 함께 잡는다.
이 셋 중 하나라도 빠지면 결과가 원작과 겉돈다.

### 3-3. 받기 — 한 줄로 끝난다

```powershell
납품처리.bat --from assets/raw/llm/_batch/시범/_제출
```

검증 → 채택(시트는 그리드 컷팅) → **설치**까지 간다. 카테고리는 파일명 id로 자동 판별한다.

- `--dry-run` 검사만(파일을 옮기지 않는다)
- `--force` 검증 FAIL이어도 설치(사람이 판단한 경우)
- 인자 없이 실행하면 `10_submitted` 전체를 훑는다

반려되면 `10_submitted/_feedback/<카테고리>/<파일>.md`에 **재요청 문서**가 생긴다
(원본 의뢰문 + 자동 검증 결과 + 다음 버전 번호). 그 파일을 그대로 다시 던지면 된다.

## 4. 개별 의뢰 (묶음을 쓰지 않을 때)

**규칙은 하나: `prompt.md` 전문 + 그 안 "입력 (첨부)" 목록의 파일 전부.**
목록의 `../foo.png`는 한 단계 위(카테고리 루트)의 공용 참조다.

- **이미지를 빼지 마라.** `orig_*.png`가 원작 화풍의 1차 근거다 — 빠지면 규칙 문장만으로는
  화풍이 안 잡힌다.
- 한 번에 하나씩. 같은 세션에서 반려 사항을 던져 재생성해도 된다.
- 납품은 `assets/raw/llm/10_submitted/<카테고리>/<id>_v1.png`.
  **`<id>`는 패키지 폴더 이름과 글자 단위로 같아야 한다**(다르면 원본 의뢰문을 못 찾는다).

### 프롬프트에 이미 들어 있는 것 — 따로 덧붙이지 마라

- **스타일 바이블 전문** — "원작 도트를 베이스로 후기 클래식 JRPG로 격상"
- **베이스라인 표** — 기존 아트 실측값(고유색·AA·외곽선 비중·채도/명도) ↔ 리메이크 타깃.
  원작 수치는 하한선이지 목표가 아니다
- **서브팔레트** — 같은 계열 아트에서 뽑은 12~16색 + hex 목록(256색 마스터는 지시를 흐린다)
- **격자 템플릿**(`grid_template.png`) — 정확한 캔버스 크기의 빈 격자. **불투명 순수 마젠타
  선만** 긋는다(남아도 키잉이 지운다). 설명·행 이름은 `grid_guide.png`로 분리돼 있고
  그 캔버스는 일부러 크기가 다르다(그 위에 그리면 규격 위반으로 반려된다)
- **정체성 체크리스트** — 고정 서술 토큰을 "그림에 실제로 보이는가" 항목으로 되돌려 준다
- **금지 목록 + 납품 전 자기검증**

## 5. 심사 보드·셀 편집기 (눈으로 보고 싶을 때)

```powershell
심사실행.bat        # http://127.0.0.1:8643/tools/review/review_board.html
```

- 카드 = 원본 참조 | 납품물 | 스타일 앵커 3열 비교 + 자동 검증 배지
- **승인** → 채택 + **설치까지 자동**(예전에는 20_processed에서 멈췄다)
- **반려** → 사유 입력 시 재요청 md 자동 생성, 납품물은 `_rejected/`로
- **[셀 편집]** → `sprite_fixer.html`. 통째로 다시 그리게 하지 말고 그 자리를 고친다:

| 도구 | 쓰는 때 |
|---|---|
| 자동 정리 | 키잉 → 잔선 제거 → 알파 이진화 → 색 양자화 → 정렬 스냅을 한 번에 |
| 계약 격자로 재배치 | 캔버스 크기·셀 수가 어긋난 납품 |
| 정렬 스냅 / 방향키 | 셀 안 인물이 뜨거나 치우쳤을 때 |
| Shift+드래그 | 라벨 글자·군더더기 지우기 |
| Alt+클릭 → 이 색 전역 삭제 | 특정 색 오염 제거 |

저장하면 **다음 버전 번호로 재납품**되어 같은 심사 흐름을 다시 탄다.

> 승인 동작은 카테고리에 따라 다르다 — 시트 계열(monsters·npcs·effects·battle_cuts·
> battle_actors)은 `process_llm_sheet`가 컷팅한 뒤 **원본을 삭제한다.** 원본을 남기고
> 싶으면 승인 전에 복사해 둔다.

## 6. 자주 나오는 반려와 대응

| 증상 | 대응 |
|---|---|
| **격자 안내선이 남음** | 셀 편집 → 자동 정리. 설치 단계도 같은 정리를 한다 |
| **고유색이 수천~수만** | 계약은 48색. 셀 편집 → 색 양자화, 또는 설치 시 자동 양자화 |
| **애니 이름·대사 글자가 박혀 옴** | 캔버스 내 글자 금지 — 반려. 짧으면 Shift+드래그로 지운다 |
| **플레이스홀더로 판정됨** | 큰 캔버스에 색 12개 미만이면 그림이 아니다. 다시 의뢰한다 |
| **크기가 틀림**(아이콘) | `python tools/convert/normalize_icon.py <납품.png> --inplace` |
| **크기·프레임 수가 틀림**(시트) | 셀 편집 → 계약 격자로 재배치. 안 되면 반려 |
| **톤이 원작과 겉돎** | 첨부 이미지를 빠뜨렸는지 먼저 확인(`orig_*.png`가 1차 근거) |
| **너무 원작 복사 같음** | 프롬프트의 "리메이크 타깃" 열을 지목해 재요청(명암 4~6단·색 24~48) |
| **배경이 흰색/체커보드** | 반려. 투명 또는 마젠타 `#FF00FF`만 허용 |

자동 판정이 잡는 것 / 못 잡는 것의 경계는 [LLM_WORKFLOW.md](LLM_WORKFLOW.md) §7에 있다.
**사람이 봐야 하는 것**: 같은 인물로 보이는가 · 캔버스 안 글자 · 동작의 연속성 · 게임 내 크기감.

## 7. 채택 이후

`납품처리.bat`(또는 보드 승인)이 `assets/sprites|portraits|icons|keyart|effects|battle_cuts`로
설치까지 한다. 확인:

```powershell
python tools/dev/asset_status.py     # 공백이 줄었는가
검증실행.bat                          # 관문 18종 (에셋 배선 감시 포함)
```

게임에서 바로 보려면 `게임실행.bat`.

## 8. 막힐 때

| 증상 | 확인 |
|---|---|
| 심사 보드가 비어 있다 | `10_submitted/<카테고리>/`에 `.png`가 있는가 |
| 3열 비교에 원본이 안 뜬다 | 파일명 `<id>`가 패키지 폴더명과 정확히 같은가 |
| `납품처리`가 "카테고리를 못 찾았다" | 파일명 id가 스펙·패키지에 없다 — 오타이거나 패키지를 안 만들었다 |
| 포트 충돌 | `python tools\review\review_server.py 9000` 후 URL 포트만 바꿔 접속 |
| `python`을 찾을 수 없다 | PATH 확인. `py -3 tools\convert\...`로도 실행된다 |
| 현황판이 낡았다 | `현황판.bat`이 매번 다시 굽는다(파일은 gitignored) |

## 주의

- **원본 의뢰문(prompt.md)의 규격·금지규칙을 임의로 줄이지 마라** — 그리드·배경 규칙 위반이
  1차 반려의 주원인이었다.
- 이미지 LLM에게 "리터치"를 시키지 않는다. 계약은 **원본 첨부 + 신원 유지 재창작**이다.
- 마젠타 배경(`#FF00FF`)은 허용하되 **혼색·안티에일리어싱 금지** — 키잉이 깨진다.
- 진행은 **시범 1~2건 → 합격 시 전체 → 부분 재생성**. 톤이 안 맞은 채로 전량을 뽑으면
  전부 다시 해야 한다. 합격본(`_remake.png`)은 다음 의뢰의 스타일 앵커로 자동 채택된다.
